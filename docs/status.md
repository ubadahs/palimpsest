## Pipeline (CLI)

The canonical target pipeline vocabulary is now defined as **discover → scope → prepare → evidence → adjudicate → report**. The contracts are replacement contracts: they expose no old-stage aliases or old-artifact readers. Canonical Discover, Scope, Prepare, and Evidence now have isolated dependency-injected application services plus current-version artifact writers/loaders, but none is wired into a CLI or executor. The runnable seven-stage executor (`discover → screen → extract → classify → evidence → curate → adjudicate`) has not yet been replaced and has no compatibility standing in the lean pipeline.

| Area | Command | Status | Notes |
|------|---------|--------|--------|
| Canonical lossless Discover | Not CLI-wired | Implemented | `runCanonicalDiscover` preserves the declared provider/query boundary, every returned citing-paper disposition, every citation occurrence, per-occurrence zero/multi/failed claim extraction outcomes, non-destructive candidate membership, deterministic cap dispositions, and exact request/response artifact references. `buildCanonicalDiscoverArtifact` creates the versioned lean envelope; the canonical writer/loader validates identity and tamper hashes. Seed grounding and family inclusion are deliberately absent from Discover. |
| Canonical membership-freezing Scope | Not CLI-wired | Implemented | `runCanonicalScope` consumes only a validated current `discoverArtifactSchema` envelope. It accounts for every candidate disposition, groups only same-seed exact-normalized candidates, freezes each selected candidate's complete source-claim and citation-occurrence membership, materializes seed text once per seed, and annotates every family with `grounded`, `ambiguous`, `not_found`, `seed_text_unavailable`, `acquisition_failed`, `grounding_failed`, or `invalid_grounding_output`. Typed nonfatal provider failures become `grounding_failed`; `invalid_grounding_output` is reserved for malformed structured output or failed exact-quote verification. `not_found` cannot carry accepted evidence. Grounding outcomes never expand or drop membership. `buildCanonicalScopeArtifact` and the current-version writer/loader preserve exact Discover lineage, immutable seed blocks, quote verification, and request/response provenance. |
| Canonical family × occurrence Prepare | Not CLI-wired | Implemented | `runCanonicalPrepare` parses and tamper-verifies current Scope plus its exact current Discover ancestor before adapter execution, cross-checks membership, and emits one complete `PreparedCitationInstance` per frozen family × occurrence pair. IDs depend only on versioned family ID + occurrence ID. Every record carries both the complete family source-candidate/source-claim ledger and exact nonempty occurrence-local subsets, preventing another mention's wording from leaking into classification. Exact Scope grounding and full Discover seed/citing-paper/occurrence data, verbatim context, locators, parser and bundle provenance survive unchanged. Deterministic/model/external classification is Zod-validated with exact provenance; ambiguous and nonfatal failed classifications remain records, while fatal provider failures stop the stage. Pair accounting forbids additions, omissions, duplicate IDs/pairs, and sampling. `buildCanonicalPrepareArtifact` plus the current-version writer/loader bind both inputs and detect tampering. Production adapters, CLI, and executor wiring remain unimplemented. |
| Canonical cited-manuscript Evidence | Not CLI-wired | Implemented | `runCanonicalEvidence` parses and tamper-verifies current Prepare plus its exact current Scope ancestor before any reranker call. It retrieves only over Scope's immutable seed-text materialization and emits exactly one outcome per Prepare record, including classification/grounding failures. Reusable family runs use one honest Scope-family query across occurrences; citing context, local extracted wording, classification, and Scope support spans never boost BM25. Fixed-window chunk IDs derive from seed/source location/text/config and preserve exact untruncated text, offsets, sections, and artifacts. Raw BM25 scores/ranks/candidate sets remain immutable. Optional relevance-only model reranking produces a separate version with strict candidate IDs and request/response provenance; disabled mode makes no calls, nonfatal failure is explicit with unchanged BM25 selection, and fatal provider failure stops Evidence. Unavailable text, acquisition failure, no lexical match, and retrieval/rerank failure remain distinct. The current-version writer/loader validates complete accounting, dangling references, ranking/selection consistency, exact input lineage, and tamper hashes. Adjudicate, production reranker adapters, CLI, and executor wiring remain unimplemented. |
| Claim discovery | `discover` | Done | **`attribution_first` is the default** (same as `pipeline` without `--strategy`; use `--strategy legacy` for seed-side claim extraction). Two strategies selectable via `--strategy`: `attribution_first` harvests citing mentions from a probe set (bounded parallel harvest + extract), extracts attributed claims, collapses identical normalized tracked-claim text per DOI before grounding, grounds families with bounded parallel LLM calls, conservatively dedupes exact and near-duplicate families (exact match includes same tracked claim even when grounded paraphrases differ), then ranks and shortlists with a greedy diversity filter on citing-paper overlap (Jaccard ≥ 0.85 skips near-duplicates). Default `--shortlist-cap` **5**. `legacy` extracts seed-side claim units and optionally ranks by citing-paper engagement. Discovery LLM defaults (legacy extraction, attribution-first extraction, and seed-family grounding during discovery) default to `claude-haiku-4-5` with extended thinking **disabled** (`--thinking` / `--discover-thinking` to enable). JSON + Markdown artifacts plus persistent sidecars (neighborhood, probe, mentions, attributed claims, family candidates, grounding trace) |
| Bootstrap / health | `doctor` | Done | Config + taxonomy sanity check, GROBID health required, reranker health optional |
| Database | `db:migrate` | Done | SQLite migrations; paper cache tables included |
| Claim-family qualification | `screen` | Done | Requires `ANTHROPIC_API_KEY`: full-manuscript LLM `claimGrounding` (verbatim-quote verification), `*_pre-screen-grounding-trace.json` diagnostic sidecar (prompt, raw response, usage); centralized full-text acquisition for seed parsing with provenance; claim-scoped citing filter (title/abstract BM25); neighborhood + claim metrics; OpenAlex/S2; dedup; auditability; JSON + Markdown reports. Seed grounding defaults to `claude-sonnet-4-6` with thinking enabled. The grounding trace now stores an ordered `records[]` collection so multiple same-DOI tracked claims do not overwrite one another. Accepts shortlists emitted by the current attribution-first, seed-side, and manual-entry paths. Ungrounded claims (`not_found` grounding) no longer block downstream — treated as a fidelity finding worth surfacing. **Thin-screen path**: when `attribution_first` discovery produces a reusable `DiscoveryHandoff`, screen skips DOI resolution, OpenAlex re-fetch, and LLM claim grounding through `runPreScreenFromHandoff`. Fresh and resumed runs both consume the versioned validated handoff boundary; resume requires `inputs/discovery-handoffs.json`. The citing-paper list carried by the handoff (up to 200) is also larger than the standard screen cap (50). |
| Citation context extraction | `extract` | Done | Centralized full-text acquisition, JATS-first parsing, validated PDF -> GROBID parsing, normalized citation mentions, citation-context outcomes + inspection artifacts. **Mention reuse**: in `attribution_first` pipeline runs, papers that were probed during discovery have pre-harvested mentions in the `DiscoveryHandoff`; the extract stage reads those directly and skips the full-text fetch + parse. Papers outside the probe budget fall back to the standard full-harvest path. |
| Evaluation-task construction | `classify` | Done | Citation roles, evaluation modes, `EdgeEvaluationPacket`, classification reports |
| Cited-paper evidence | `evidence` | Done | DOI/PMCID/PMID/title+author+year resolution, centralized full-text acquisition with method tracking, BM25 retrieval for all evaluation tasks, **deferred LLM reranking** (Haiku, only on curated audit records post-sampling) or optional local HTTP sidecar reranker, abstract-only downgrade, parsed-paper cache reuse; `--no-llm-rerank` to disable |
| Evaluation sampling (old executor) | `curate` | Done | Samples an evaluation worksheet + JSON from evidence results; this is not canonical `prepare` and will move to a separate future evaluation workflow. Default target size **20** (`sampleAuditSet` / pipeline `--target-size`). `manual_review_role_ambiguous` tasks stay eligible but are capped to at most **25%** of the target when sampling |
| LLM adjudication | `adjudicate` | Done | Anthropic via centralized LLM client, centralized telemetry, agreement reports; default is `claude-opus-4-6` with extended thinking (`--no-thinking` to disable). **Advisor mode** (`adjudicateAdvisor: true` / `--advisor`): Sonnet+thinking first pass on all audit records, then escalates `judgeConfidence === "low"`, `verdict === "cannot_determine"`, or bundled citations with `medium` confidence to Opus+thinking. **Enabled by default**; configurable via `adjudicateFirstPassModel`. Per-pass telemetry exposed as `firstPassTelemetry` / `escalationTelemetry` / `escalationCount` in the output artifact. **Citation scope annotation**: adjudicator prompt wraps sentences attributed to the seed paper with `▶ ... ◀` markers using `seedRefLabel` from reference resolution, disambiguating multi-reference paragraphs. Optional `fidelityVectorTrace` is disabled by default; when enabled it samples final active records using retrieved evidence snippets, defaults to Sonnet, reports `"fidelity-vector"` telemetry, and does not alter canonical verdicts. **Vector-first adjudicator** is opt-in via `adjudicationMode: "vector_first"` / `--adjudication-mode vector_first`: it samples vector axes first, adaptively adds samples for simple borderline cases, accepts clear axis-derived verdicts, and escalates risky records to the existing categorical adjudicator using original audit records. |
| Benchmark workflow | `benchmark:*` | Done | Blind export, keyed diff, candidate summary, and approved-delta apply for adjudication datasets; excluded-only adjudication diffs are ignored; blind export strips optional `fidelityVectorTrace` diagnostics and vector-first routing provenance from active records |
| Full pipeline | `pipeline` | Done (old executor pending replacement) | `--input` / `--shortlist` / `--run-id` / `--seed-pdf`. Fresh CLI runs default `discover` strategy to `attribution_first`. Stored defaults include `discoverShortlistCap` **5**, `curateTargetSize` **20**, `adjudicationMode` **categorical**, and optional fidelity vector tracing disabled (`adjudicateFidelityVectorTrace: false`). Resuming with `--run-id` (as the UI does) reads current `analysis_runs.config_json`: `stopAfterStage` halts after the named current executor stage, `forceRefresh` maps to paper-cache policy, `evidenceLlmRerank` toggles LLM evidence reranking, `adjudicateModel` / `adjudicateThinking` / `adjudicateAdvisor` / `adjudicateFirstPassModel` / fidelity-vector and vector-first config pass through to adjudication, `familyConcurrency` bounds parallel extract→adjudicate work across greenlit families after `screen`. `extract` and `classify` reuse run-scoped cached results for identical citing-paper neighborhoods. **Attribution-first handoff**: fresh and resumed runs consume only the current versioned, content-hashed, Zod-validated representation; fresh maps are serialized and reconstructed at the shared boundary before `screen`/`extract`. Missing, unreadable, invalid, tampered, or shortlist-incomplete sidecars fail resume. Unversioned handoffs are rejected. Fatal Anthropic billing/quota/auth failures fail the run and mark later family stages `blocked` with the provider reason instead of silently completing |

## Retrieval and Parsing Notes

- PDF ingestion now requires **GROBID**. `pdf_text` remains a provenance value for scientifically preserved raw inputs; new runs emit `grobid_tei_xml`.
- Full-text retrieval is now centralized in one acquisition layer shared by `discover`, `screen`, `extract`, and `evidence`.
- Provider metadata is treated as retrieval hints. The acquisition layer preserves requested identifiers, ranks candidates, validates payloads, and records the winning method plus every attempted path.
- GROBID is invoked only after a response has been validated as a real PDF. HTML landing pages, interstitials, and challenge pages are classified explicitly rather than surfacing as generic parser failures.
- Citing and cited full text are normalized into one parsed-document representation with:
  - structured blocks
  - bibliography references
  - resolved in-text citation mentions
- Canonical Evidence uses deterministic fixed-window chunks over exact Scope blocks, a family-claim-only BM25 first pass, and an optional separately versioned relevance rerank. It never truncates machine evidence or uses citing-side context/classification/grounding spans as lexical boosts.
- The temporary executor still supports its LLM/local reranker path, abstract-only downgrade, and compact display spans. Its BM25 query now uses only the declared family claim; mode-aware citing context remains confined to the separate temporary rerank pass.
- Stage artifacts now record acquisition provenance so reports can say how each paper was materialized (`pmc_xml`, `biorxiv_xml`, landing-page XML, or validated direct PDF via GROBID).

## How to update this file

Edit the tables when a command’s behavior materially ships or when scope changes. Bump **Last updated** to the change date.

When the **local UI** or **workspace layout** changes, verify [AGENTS.md](../AGENTS.md) and [CLAUDE.md](../CLAUDE.md) still match the repo. When **artifact paths**, **stage keys**, or **stage responsibilities** change, update [pipeline.md](./pipeline.md), [artifact-workflow.md](./artifact-workflow.md), and [ui-architecture.md](./ui-architecture.md) in the same change when possible.

Before a release or large merge, use the checklist in [README.md](./README.md) (release / large-change section) to avoid stale documentation.
