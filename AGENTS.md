## What This Project Is

CLI-first tooling for auditing citation fidelity in scientific literature. It analyzes whether citing papers faithfully represent the claims of cited papers — domain-agnostic and not limited to any single citation function. Local SQLite storage. **CLI and JSON/Markdown artifacts are authoritative; there is no hosted multi-user product. A local-only Next.js app in `apps/ui` may orchestrate CLI subprocesses and inspect artifacts.**

**What is actually built today** is summarized in `docs/status.md` (CLI-aligned; update when phases land). Authoritative workflow docs are `docs/pipeline.md`, `docs/status.md`, and `docs/adjudication-rubric.md`.

## Architecture

```
apps/ui/      Local-only Next.js (App Router pages + Pages API); depends on root via workspace
src/
  stages/       One folder per stage (discover, scope, prepare, evidence, adjudicate, report): run.ts builds the
                stage artifact; adapters.ts holds its production model and network calls; prompts.ts its prompts;
                plus helpers only that stage uses (claim clustering, candidate selection, seed codebook, role rules,
                retrieval, adjudication packet and whole-seed-text prompt, report Markdown). production.ts is what
                every stage adapter shares
  pipeline/     Orchestration: executor, provenance store, stage paths, cost summary, run tracking, the adapters for all six stages
  cli/          Command entrypoints (index.ts dispatches to commands/)
  config/       Env loading (Zod-validated), AppConfig construction, and PROMPT_VERSIONS
  domain/       Core taxonomy types and decision logic (pure)
  health/       Health checks shared by CLI (doctor) and UI
  integrations/ External provider adapters (bioRxiv, OpenAlex, Semantic Scholar); centralized LLM client (llm-client.ts)
  retrieval/    Full-text acquisition, parsing, BM25
  review/       Append-only report-bound human review store (package export: palimpsest/review)
  evaluation/   Frozen-report comparisons and blind annotation (package exports: palimpsest/evaluation, palimpsest/evaluation/server)
  storage/      SQLite schema, migrations (sequential .sql files), repositories
  shared/       Cross-cutting primitives
  contract/     Shared stage/run types; artifacts/ holds per-stage artifact schemas and lineage checks; package exports: palimpsest/contract (+ /server)
tests/          Mirrors src/ structure
```

### Key Patterns

- **Boundary validation**: All external data (API responses, env vars, LLM outputs, XML) is Zod-validated before entering the domain layer. Types are inferred from Zod schemas (`z.infer<typeof schema>`). Each stage builds its boundary parser from `createBoundaryParser` in `src/shared/boundary.ts`; deterministic ordering and deduplication come from `src/shared/order.ts`.
- **Artifact integrity, once**: `src/contract/artifacts/index.ts` is a barrel over `src/contract/artifacts/{envelope,primitives,discover,scope,codebook,prepare,evidence,evidence-statuses,adjudicate,report,checks,seed-section-role}.ts`. Two checks apply to every artifact: its identity hash over payload + decisions, and that it names the exact inputs it was built from in stage order (`validateStageInputLineage`). Beyond those, a stage schema checks only a method rule (what a verdict needs, which denominator a rate uses, that every input has exactly one outcome) or data its builder did not produce (model replies, adapter output, cached papers, stored codebooks); re-deriving what a builder just wrote is left to the builder's tests.
- **Replacement rule**: Delete what a change supersedes: aliases, compatibility readers, and old-run fallbacks; old runs need not remain readable. Preserve scientific raw inputs (including frozen evaluation datasets and the human labels on them), provenance, and git history.
- **Production pipeline**: The public CLI, run registry, UI, and artifact layout execute only `discover → scope → prepare → evidence → adjudicate → report`. Fresh runs are DOI-first (`pipeline --input <dois.json>`). Public stage vocabulary is exactly these six keys.
- **Discover and Scope**: Discover enumerates the whole citing neighborhood (metadata only; OpenAlex `page=` paging sorted by publication date, `neighborhoodLimit` default 10,000 is a safety cap and coverage says `truncated` past it), samples the probe set from the frame of works not marked closed or abstract-only (`isInSamplingFrame`), stratified by year band × type group (article/review/other), with `allocateProbes` giving each probe to the stratum whose probed works stand for the most frame works, and records each stratum's inclusion probability π = probed frame works / frame works, harvests probed papers `discover.fetchConcurrency` at a time (non-scientific, excluded from the resume conflict check; output keeps neighborhood order), emits one seed occurrence per exact citation group, clusters paraphrased claims across citers into one candidate per seed finding (model equivalence with an exact-text fallback; one request when a seed's claims fit a block of 150, otherwise `src/stages/discover/claim-clustering.ts` groups exact text, splits units into BM25-similar blocks, clusters blocks side by side, and merges block clusters in rounds over one representative each, recorded as `equivalence.method: "blocked_model"`), annotates candidates, and selects either an adaptive 15–25 family portfolio under a prepared-record budget or, with `candidateSelection.mode: "all"`, every candidate, without grounding. `probeBudget: "all"` probes every enumerated citer; `--census` sets both. Scope consumes its verified envelope, accounts for every candidate, freezes exact family/occurrence membership, materializes seed text once per seed, and records verified grounding as a non-excluding annotation. No shortlist, handoff, or legacy stage artifact is read.
- **Seed codebook (Scope annotation)**: Scope also builds a codebook of the seed's citable statements from the seed paper (`src/stages/scope/seed-codebook.ts`: three `seed-codebook` calls sharing the seed text as a cached prefix — results/headline, relayed background/methods, organise into themes and entries with a non-empty headline theme — every quote exact-verified, unverified entries dropped and counted) and tags every Discover claim, one `codebook-tagging` request per claim with the codebook as the cached prefix (1–3 entries, a theme alone, or none; failures are typed `tagging_failed`). The verified codebook is frozen in SQLite (`seed_codebooks`, keyed by seed id, seed-text hash, `SEED_CODEBOOK_PROCEDURE_VERSION`): reused when the key matches, never deleted by `db:gc`, not replaced by `--force-refresh`, only by `--regenerate-codebook`. Scope records `codebooks` (generated/reused/failed/seed_text_unavailable) and `claimTags`; Report adds `seedCodebooks` (per-entry and per-theme tables, theme roll-up, joined through `evaluatedClaimRecordIds`). It is additive: families, selection, record identity, and verdicts never read it.
- **Prepare and Evidence**: Prepare emits one complete stable record per scoped family × citation occurrence, preserving complete and occurrence-local claim membership with typed classification. Family-level data (Scope families, seeds, candidates, claims, citing papers) is stored once on the payload; records keep only their occurrence, the ids of their occurrence-local candidates and claims, and their classification. Consumers join with `resolvePreparedRecords`. Role classification is two-pass: a free deterministic regex pass, then `prepare.roleClassifierModel` for its `unclear` verdicts only, `modelConcurrency` at a time with results kept in input order. Records without a verified support span never reach the model and stay `manual_review_extraction_limited`. Evidence emits one outcome per Prepare record over immutable Scope seed text; BM25 queries occurrence-local claims with the Scope family claim as fallback (fused by reciprocal rank), and relevance reranking (on by default) is an immutable separate version that sees each chunk's section role and whether the seed block cites other work. Grounding pins apply in both branches. When verified pins fill the selected packet, Evidence skips the reranker with a typed status and Report counts the skip. There is no sampling or `curate` stage.
- **Adjudicate (uncalibrated)**: Adjudicate emits one categorical `F`/`D`/`E`/`U` result or typed operational non-verdict per Evidence record, using deterministic gates and one model request per eligible record. By default (`adjudicate.evidence: "seed_text"`) the model reads the whole seed text, rebuilt from the Evidence corpus so the stage needs no extra input: the seed text is a prompt prefix cached across a seed's records, the first request per seed writes the cache alone, and the verdict rests on quotes exact-verified against the seed blocks (`seedQuotes`; `modelCitedChunkIds` are the corpus chunks holding them, selected by Evidence or not). An unverifiable quote is dropped and counted, an `F`/`D`/`U` left with none is `invalid_output`, and an `E` may quote nothing. `selected_chunks`, or a seed text over `SEED_TEXT_MAX_CHARACTERS`, reads only Evidence's selected chunks. Gates are identical in both modes. Ambiguous/manual-review roles stay gated and are not auto-broadened to the model. Confidence never routes a different model or path; advisor/vector modes are not product behavior. It is runnable but **uncalibrated**: blinded human calibration is required before trust claims.
- **Local evaluation**: `eval` freezes a finished report into cases under gitignored `data/evaluations/`. It is not a seventh pipeline stage and does not rewrite artifacts. Cases are rebuilt with the current code over the run's frozen inputs: records today's packet gate would hold back are left out, and seed section roles are inferred again. A dataset also stores each seed's full text, so an Anthropic provider with `adjudicationEvidence: "seed_text"` can adjudicate from the whole paper (cached prefix, exact-verified quotes) instead of the selected chunks. `--mutations` adds constructed cases, edits of restatements a human labelled `F` whose expected verdict is known: distortions (expected `D`/`E`) measure missed distortions, and wording-only controls (expected `F`) measure false alarms. They are scored apart from human labels, and chunk and whole-paper providers are compared only on cases whose evidence grounding pins fix. Case ids hash case content, and human labels point at case ids, so the stored keys of a case (including the adjudicate packet's, such as `familyTrackedClaim`) never change.
- **Report**: Report tamper-verifies the full preceding chain and deterministically writes authoritative JSON funnel/rate/trace accounting, the seed codebook view, plus Markdown rendered only from that JSON. Markdown lists every restatement and traces every record only up to 200 records; above that it summarizes each family (counts, verdict shares, two examples per verdict with D and E first) and points to the JSON, so its size follows families. Funnel accounting includes unique citation-group coverage, the provider-reported neighborhood total and its coverage (so the sampling denominator is stated), probe strata with inclusion probabilities, full-text access channel, materialization and harvest loss reasons, bibliography match method, adaptive portfolio deferrals, and manual-review queue splits. `selectionAudit` carries each candidate's portfolio component scores and each record trace carries its citation-role signals. F/D/E/U rates use the adjudicated-record denominator; operational non-verdicts are excluded. `weightedRates` add F/D/E/U rates with each adjudicated record from a frame work weighted 1/π of its stratum, estimating rates over the sampling frame (records from works outside it are left out); the unweighted rates stay as the observed sample counts.
- **Storage cleanup**: `analysis_run_stages.family_index` stays because it is part of an immutable primary key. `db:gc` deletes aged analysis-run and LLM-cache SQLite rows, plus `llm_batch_requests` rows past the 29-day batch results retention (not artifact directories or stored seed codebooks); `runs:gc` deletes superseded stage attempts a `--rerun-from` left on disk plus the provenance blobs only those attempts referenced.
- **Run-config defaults**: `RUN_CONFIG_DEFAULTS` in `src/contract/run-types.ts` is the single source for nested discover/scope/prepare/evidence/adjudicate defaults (schema, CLI empty parse, UI form).
- **One rubric**: Citation-role and F/D/E/U definitions live in `src/domain/rubric.ts`. Production prompts (role classification, both adjudication modes) render them, and evaluation gives jev/djev providers the same definitions as criteria. Changing a definition changes production prompts, so bump the prompt versions that render it and the evaluation prompt revision (`CURRENT_PROMPT_REVISION`, with `promptsSeen` saying which providers and tasks the new revision changed). The human review form keeps its own plain wording on purpose.
- **Domain taxonomy**: Core enums (FidelityVerdict, MutationKind) live in `src/domain/taxonomy.ts`, each as a Zod schema with an inferred type.
- **Typed error handling**: Expected failures (unresolved citation, no open-access text, invalid LLM JSON) use `Result<T>` return values (`{ ok: true; data: T } | { ok: false; error: string }`), not thrown exceptions. Throw only for programmer errors.
- **Centralized LLM client**: Anthropic calls (attributed-claim extraction, claim clustering, citation-role classification, seed grounding, seed codebook, codebook tagging, evidence reranking, adjudication) go through `src/integrations/llm-client.ts` and all use `generateObject` with provider-enforced structured output against the adapter's response schema. Every call is tagged with a `purpose` and returns `LLMCallRecord` telemetry; `getLedger()` aggregates per-run cost by purpose. The executor's `createRunCostTracker` rewrites `cost-summary.json` after every call (earlier attempts read once as a baseline) and backs `--max-cost`, which the client checks before each request; a `spend_limit` error aborts the stage rather than gating records. `--batch` (not run config, like `--max-cost`) swaps the provider's `fetch` for `src/integrations/batch-transport.ts`: stages get unbounded concurrency, quiet queues of five or more requests go out as one Message Batch (smaller ones direct), and each caller gets a synthetic `Response` from its batch result, so validation, retries, and classification are unchanged. Batched records carry `transport: "batch"` and half-price `estimatedCostUsd`; under `--max-cost` each queued request reserves an expected cost (cache-read prefix, 2,000-token output floor or twice the observed mean), so the limit is approximate. Batched shared prefixes use the 1-hour cache TTL. Submitted `custom_id`s (hash of body and headers) live in `llm_batch_requests` so a resume takes a pending batch's result instead of paying twice. Each prompt has one version in `PROMPT_VERSIONS` (`src/config/prompt-versions.ts`): it is recorded in provenance and is the call's `exactCache: { keyVersion }`, so identical requests return cached responses without hitting the provider and a bumped version misses. Run-config defaults name the current models (`claude-haiku-5-5`; `claude-sonnet-5-5`, which also adjudicates). Provider prompt caching applies only to a request that names a shared prefix (seed grounding, seed codebook, codebook tagging, whole-seed-text adjudication). Run config accepts only the models in `claudeModelValues` (`src/shared/anthropic-token-cost.ts`, beside their prices). Each thinks adaptively, so a call carries one thinking `effort`; some cannot be told to stop, so a call site with thinking off sends the lowest effort (`resolveThinkingEffort`).
- **Citation scope annotation**: The adjudicator prompt wraps sentences attributed to the seed paper with `▶ ... ◀` markers, using exact-verified support-span offsets and the occurrence's own marker position (`markerSpan`, offsets in `rawContext` recorded by the parser) before windowing, so repeated numeric markers and group fragments like `68]` resolve by position; only an occurrence without an exact position falls back to the resolved reference identity. Sentence splitting protects abbreviations such as `et al.`. Unverified targets and markers that lack claim-bearing text gate to `manual_review_extraction_limited`. The `seedRefLabel` (e.g. "Adeyemi and Okonkwo, 2009") is populated at mention-harvest time from the matched bibliography entry's `authorSurnames` + `year` and propagated through the pipeline.
- **Verified claim support spans**: Discover exact-verifies extraction `supportSpanText` against occurrence `rawContext` and persists offset-bound `supportSpan` objects. Prepare/Adjudicate fail closed when occurrence-local claims lack a verified span (`manual_review_extraction_limited`). Deterministic role classification prefers verified span text over marker-local verb windows.
- **Local seed PDF**: `--seed-pdf <path>` on a single-DOI `pipeline` run bypasses open-access lookup for that seed paper, reads the local PDF, and sends it to GROBID. The UI new-run form has an optional PDF upload field. The path is persisted only as `scope.seedPdfPath`; multi-DOI runs reject a single shared PDF.
- **GROBID concurrency** (`GROBID_CONCURRENCY`, default 2): PDFs sent to GROBID at once, bounded separately from `discover.fetchConcurrency` because a local container times out under more; waiting for a slot does not count against the request timeout.
- **Institutional proxy** (`INSTITUTIONAL_PROXY_URL`): When set (e.g. `https://libproxy.mit.edu/login?url=`), the full-text acquisition layer tries open-access candidates first; if all fail, it retries the publisher's landing-page and PDF URLs through the proxy as fallback. Open access tries every provider location (`fullTextHints.locations`, each a PDF or landing page from the publisher or a repository): the publisher's version of record first, then repository copies such as arXiv. A failed paper reports the attempt that got furthest, not the last one. Successful proxy acquisitions are tagged `accessChannel: "institutional_proxy"` in the acquisition metadata. Configured via `.env` / `.env.local`.
- **Dependency injection**: Pipeline orchestration accepts adapter interfaces so integration tests can use mocked adapters without network calls.
- **Migrations**: Sequential `.sql` files in `src/storage/migrations/` named `NNNN_description.sql`. Applied via `schema_migrations` table. Never modify existing migration files.
- **ESM modules**: The project uses `"type": "module"` with NodeNext resolution. All local imports must use `.js` extensions.
- **Type imports**: ESLint enforces `import type` for type-only imports (`@typescript-eslint/consistent-type-imports`).
- **UI inspector contract**: Stage detail UIs should consume the typed payloads from `src/contract/inspector-payloads.ts` via `buildStageInspectorPayload()` in `src/contract/selectors.ts`, not raw artifacts or `unknown` casts. When stage artifact shapes change, update the payload builder and keep the contract tests passing. Report Families read the `familyMutations` section of the Report artifact (`buildReportInspectorFamilies` joins inspector rows onto it; it is not a second producer), and each family carries `recordIds` into the summary's rows rather than a second copy of them, with the Families tab rendering 50 restatements at a time; human review is an append-only sidecar under `palimpsest/review` / `data/runs/<runId>/review/<reportArtifactId>/`, never a seventh stage and never a rewrite of machine artifacts. The review workspace opens blinded, the reviewer records their own `F`/`D`/`E`/`U`/`not_adjudicable` label plus mutation kinds, and agreement is derived at export time; the CSV export collapses records to `family × citing-paper × claim` units via `buildClaimUnitKey`, the same rule the Report counts with.

### Domain Model

Fidelity labels are `F` (faithful), `D` (distortion), `E` (error), `U` (uncertain). A `D` names the dimensions that moved (`mutationKinds`).

## TypeScript Strictness

The tsconfig enables `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`, and all strict flags. `no-explicit-any` is enforced in src/ but relaxed in tests/.
